# `midi-scenes` — MIDI SCENES (MIDISC2.1)

MIDI-driven scene locks, built from
[bkkbrls-del/midisc](https://github.com/bkkbrls-del/midisc) (submodule
`upstream/` at `52eaab0`, MIDISC2.1). `Kind.CF_PATCH`: five linker-placed
DRAM units (`msc21_ram` / `a` / `b` / `c` / glue), hooks from
`upstream/tools/midisc/hooks21.py`, plus octabam's `engine_follow` detour
at `0x400a4ba0`. No DSP code, no menu row.

Stock 1.40C has no per-scene parameter lock over MIDI: XF morph reads one live
8×30 lock table that only the panel writes. midisc adds a second, addressable
table and rewires scene hold, XF morph, part save/reload and the scene
clear/copy/paste rows to read and write it when a MIDI event is driving.

## MIDISC2.1

Upstream caves are regenerated by `tools/gas_port21.py` from
`release21.json` (only bytes that file writes; gaps are `.skip`). Prove with:

```bash
OCTABAM=<this repo> PYTHONPATH=modules/midi-scenes/upstream/tools \
  python3 modules/midi-scenes/upstream/tools/gas_port21.py
```

`tools/verify/verify_midiscenes.py` runs that under `make check`.

### Behaviour vs 8.2 (upstream TECH)

- Pre-trig XF / scene activation on the published playback path
- Queued pattern/Part scene publish at the native first-step boundary
- Sequencer ACT bank/pattern commit (`0x400a44f4`) syncs `play_bank` / `play_part`
- `due_unlocked` respects the native active-lock mask
- Native CC loops before same-track note-ons
- Recorder/master descriptors restored; scene scratch off native clipboard

### Stock sites new vs the old 8.2 MIDI SCENES port

| site | role |
|------|------|
| `0x4004ABC0` | part-window / apply path |
| `0x40062216` | bank/part helper |
| `0x40087EAC` | bank publish related |
| `0x4009FAAA` | MIDI/engine path |
| `0x4009FE4E` | poke into his continuation |
| `0x400A169A` | MIDI sequencer path |
| `0x400A19DA` | MIDI sequencer path |
| `0x400A1D32` | MIDI sequencer path |
| `0x400A3C2A` | MIDI/engine path |
| `0x400A44F4` | pattern-commit sync |
| `0x400A4BA0` | octabam `engine_follow` |

`msc_follow` / `msc_kit_commit` / `engine_follow` are exported for a later
KITS PR; nothing in octabam calls them yet.
